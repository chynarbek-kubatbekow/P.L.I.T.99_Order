# ПЛИТ №99 — Сайт лицея

Официальный сайт Профессионального лицея информационных технологий №99 при Президенте Кыргызской Республики.

Настройки безопасности, результаты локальных проверок и порядок обновления описаны
в [SECURITY.md](SECURITY.md). Для публичного сервера используйте `APP_ENV=production`:
локальный режим по умолчанию предназначен для HTTP на `127.0.0.1`, с `DEBUG=False`.
Подробный анализ по четырём переданным репозиториям, точный охват чтения и новые
регрессионные проверки — в [SECURITY_RESEARCH.md](SECURITY_RESEARCH.md).

Инструкция обновления физического сервера из GitHub — [REDEPLOY.md](REDEPLOY.md).

## Локальный запуск и сервер — отдельные режимы

Для локальной проверки используйте `run-local.ps1` на Windows или
`bash run-local.sh` на Linux. Они применяют HTTP-настройки только в дочернем
процессе и не меняют production-файл `.env`. БД, медиа и ключи берутся из
существующей конфигурации; автоматически новая пустая база не подставляется.
Если нужен отдельный набор локальных данных, задайте его в игнорируемом Git
файле `.env.local`. Не направляйте локальный профиль на рабочую удалённую БД.

На публичном сервере остаются прежние `build.sh` / `start.sh` (либо `.ps1`),
`APP_ENV=production` и HTTPS через reverse proxy. Локальный запуск слушает
только loopback и не предназначен для публикации в сети.

### Windows: проверить сайт и админку

```powershell
.\run-local.ps1 migrate
.\run-local.ps1 createsuperuser
.\run-local.ps1
```

Для существующего пользователя вместо `createsuperuser` можно выполнить
`.\run-local.ps1 changepassword ИМЯ`. Сайт: **http://127.0.0.1:8001/**,
админка: **http://127.0.0.1:8001/admin/**. Остановка — Ctrl+C в терминале запуска.
Локальный сервер автоматически перечитывает изменения Python-кода.

### Linux: локальная проверка

```bash
bash run-local.sh migrate
bash run-local.sh createsuperuser
bash run-local.sh
```

Общий вариант из активированного venv: `python scripts/local.py`.
Любая management-команда передаётся аргументами, например
`python scripts/local.py check`. Запуск из другой папки также поддерживается.

### Почему раньше возникала ошибка CSRF

Для HTML POST-форм нельзя задавать общий `Referrer-Policy: no-referrer`:
браузер может отправить `Origin: null`. На админке и контактах теперь
`same-origin`, CSRF остаётся включённой. После обновления откройте форму заново,
чтобы браузер получил исправленный заголовок. Cookies локального профиля
отделены от production. DEBUG для исправления входа включать не требуется.

## Первичная установка зависимостей

### 1. Установка зависимостей

```powershell
python -m pip install --only-binary=:all: -r requirements.txt
```

### 2. Применить локальные миграции

```powershell
.\run-local.ps1 migrate
```

### 3. Необязательно: заполнить новую локальную БД тестовыми данными

```powershell
.\run-local.ps1 seed_data
```

Этот шаг пропускайте для уже существующего сайта и при редеплое.

### 4. Создать администратора

```powershell
.\run-local.ps1 createsuperuser
```

### 5. Запустить сервер

```powershell
.\run-local.ps1
```

Сайт будет доступен по адресу: **http://127.0.0.1:8001/**.
На Linux используйте аналогичные команды `bash run-local.sh` из раздела выше.

## Административная панель

**Локальный URL:** http://127.0.0.1:8001/admin/. На сервере — `/admin/` через HTTPS-домен.

**Тестовые данные для входа (если использовалась seed_data):**
- Создайте пользователя командой `createsuperuser`

### Что можно делать в админке:

#### 📰 Новости
- Добавлять / редактировать / удалять новости
- Загружать фото-обложку или задавать эмодзи + градиент
- Загружать видеофайл MP4/MOV/WebM до 100 МиБ и 2 минут; видео выводится в статье
- Назначать категории и метку «Главная новость»
- Управлять публикацией (черновик / опубликовано)
- Фильтрация по дате, категории, статусу
- HTML новостей очищается сервером, базовое форматирование сохраняется

#### 🖼️ Галерея
- Загружать фотографии
- Добавлять видео (ссылка на YouTube/Vimeo)
- Загружать видеофайл MP4/MOV/WebM до 100 МиБ и 2 минут вместо внешней ссылки
- Сортировать по категориям (Мероприятия, Учёба, Спорт, Международное)
- Устанавливать порядок отображения
- Фотографии проверяются и сохраняются в `APP_DATA_DIR/media/`

#### Приватные отзывы

Отзывы с контактов сохраняются зашифрованными и доступны в разделе
«Приватные отзывы» сотрудникам с правом `core.view_privatefeedback` и superuser.
Для чтения нужен прежний ключ: при обновлении его нельзя заменять случайно
сгенерированным. Публичной страницы отзывов и редактирования отправленного текста нет.

## Отказоустойчивость контента

Новости и галерея читаются через Django ORM, изображения находятся в
`APP_DATA_DIR/media/`. При ошибке БД списки могут быть пустыми, а детальная страница
вернуть 404; автоматический fallback из JSON в текущем коде не реализован.
Создавайте и проверяйте резервные копии БД вместе с файлами media.

## Переход на PostgreSQL (продакшн)

Задайте `DATABASE_URL` в окружении сервиса, не записывайте пароль в `settings.py`:

```text
DATABASE_URL=postgresql://APP_USER:URL_ENCODED_PASSWORD@DB_HOST/APP_DB?sslmode=verify-full
```

Нужны доверенный CA и минимальные права runtime-роли. Миграции выполняются
отдельной ролью с DDL. Подробности и ограничения — в [SECURITY.md](SECURITY.md).
