# Видео, приватные отзывы и фронтенд — 8 ноября 2026

Версия 2. Дополнительная проверка и новые лимиты: [BACKEND-AUDIT-2026-11-08.md](BACKEND-AUDIT-2026-11-08.md).
Владелец внедрения: владелец сайта ПЛИТ №99. Область: текущая локальная
копия проекта `plit99_improved-2`. Рабочий сервер и его сетевые права не менялись.

## Что изменено

- В Django admin у новости и элемента галереи появилось поле загрузки видео.
  Для галереи выбирается тип «Видео» и один источник: файл или прежняя ссылка
  YouTube/Vimeo. Новость может иметь одновременно фотообложку и видео в статье.
- MP4/MOV/WebM, до 100 МиБ, до 120 секунд. Сервер декодирует и перекодирует
  файл в MP4 H.264/AAC, до 1280×720 и 30 fps; удаляет метаданные и дополнительные
  потоки. Исходник не публикуется. Максимум 45 секунд обработки и одна обработка
  на worker; на проде дополнительно ограничивать память/CPU учётной записи службы.
  Библиотека `imageio-ffmpeg` поставляет бинарник; на проверенной Windows версии
  использовался FFmpeg `9.0.2-essentials_build-www.gyan.dev`.
- Загруженные видео воспроизводятся с controls, без автозапуска, поддерживают
  HTTP Range/HEAD. Файл выдаётся только при привязке к опубликованной записи
  либо сотруднику с соответствующим разрешением просмотра в admin. Удаление
  записи закрывает выдачу оставшегося файла. Внешние embed-ссылки остаются
  публичными у их провайдера и не получают приватность локального черновика.
- Под картой на контактах добавлен ящик отзывов. Имя и контакты не запрашиваются.
  Публичных списков, чтения, изменения и удаления отзывов нет.
- Подпись разработчика оставлена только на контактах: 8 px (7 px на телефоне),
  внизу справа футера, отступы справа и снизу 5 px. Это конец страницы, а не
  плавающая над контентом подпись.
- Для главной подключён `static/img/hero-lyceum-enhanced.jpg`; исходный
  `hero-lyceum.jpg` сохранён. Использован встроенный ImageGen, затем JPEG-export.
  Задание: умеренно убрать шум и JPEG-артефакты, повысить чёткость, сохранить
  композицию, здание и кириллическую надпись. Это AI-реставрация для оформления,
  не документальное восстановление отсутствующих деталей; исходник остаётся
  источником фактического вида здания.

## Модель угроз, контракты и права

Активы: приватный текст отзывов, ключи шифрования, учётные записи сотрудников,
БД, новости и медиахранилище. Противники: анонимный посетитель, спам-бот,
сотрудник без права чтения отзывов, вредоносный ввод/файл, обладатель копии БД.

| Поверхность | Правило | Проверка |
| --- | --- | --- |
| `POST /contacts/feedback/` | Анонимная отправка с CSRF; только URL-encoded форма; allowlist полей; запрет дубликатов | CSRF/Origin, JSON, mass assignment, повтор полей |
| Ввод отзыва | 10–4000 символов; HTTP body ≤64 КиБ; контрольные символы запрещены | Короткий, длинный, Unicode, NUL, oversized |
| Хранение | ORM INSERT; текст шифруется Fernet с проверкой подлинности, ключ отдельно от БД | SQL/XSS payload, расшифровка, подмена шифротекста, неправильный ключ |
| Лимиты | До 5 сообщений/10 минут на REMOTE_ADDR и 200/час суммарно; общий атомарный счётчик в БД | IP/global лимит и spoofed X-Forwarded-For |
| `PrivateFeedback` | Только INSERT от публичного обработчика; в admin только view/delete по разрешениям; нет add/change | Гость, staff без разрешения, reader; попытки POST/change/delete |
| Admin-вывод | Обычный текст с HTML-экранированием; никаких mark_safe/render HTML для отзывов | Stored XSS в форме просмотра |
| Кэши и аналитика | no-store для формы/ответов и admin; текст не отражается в ошибках, URL, object_repr; GA отключена на контактах | Заголовки, отсутствие скрипта и отражения |
| Медиа | Только сотрудник загружает; декодирование, лимиты, случайное имя; сервер не скачивает URL | Настоящие MP4/WebM, ложный MIME, HTML под .mp4, playlist, timeout |
| Выдача видео | ORM-проверка публикации/прав, фиксированный путь и MIME, nosniff, sandbox | Черновик, orphan, Range/HEAD и слишком длинный Range |

Форма передаёт только `message`, `website` (honeypot) и CSRF-token. Поля owner,
role и произвольные ORM-фильтры клиент не задаёт. Сохраняются только ciphertext
и время; IP в отзыве не хранится. В счётчике — HMAC IP и временное окно.
Старые счётчики удаляются существующей командой `clear_login_throttles`.

Денежные операции, Web3, внешняя почта, публичная регистрация, multi-tenant API
и прямой browser-to-DB доступ: N/A, этих функций здесь нет. Для БД используется
server-only ORM и существующая авторизация Django admin. Новые таблицы не
открываются наружу отдельным API. Сам URL не является секретом и не заменяет права.

## Ключи и запуск

В локальном режиме ключ создаётся при первой отправке в
`APP_DATA_DIR/.feedback-key`, вне Git и публичного media. В production
автоматического fallback нет: без ключа ящик отвечает 503, текст не сохраняется.

В production задайте один из вариантов:

1. `FEEDBACK_ENCRYPTION_KEY_FILE` — приватный путь вне static/media. Пример
   указан в `.env.example`. Создать один раз командой
   `python manage.py create_feedback_key` в окружении службы. Команда не печатает
   ключ и отказывается заменять существующий файл. На Windows настройте ACL,
   разрешив чтение только учётной записи службы и ответственным администраторам:
   POSIX mode 0600 не является полноценной настройкой Windows ACL.
2. `FEEDBACK_ENCRYPTION_KEYS` — Fernet-ключи из менеджера секретов, через запятую,
   новый первым. Старые ключи сохраняются для чтения старых отзывов. Список имеет
   приоритет над файлом. Новый ключ без старого не расшифрует старые отзывы.

После установки закреплённых зависимостей примените миграцию `0004`, выполните
`collectstatic`, перезапустите службу. Сотрудникам, которым нужны отзывы,
выдайте только `core.view_privatefeedback`. Superuser имеет доступ по модели Django.
Право удаления выдаётся отдельно; массовое удаление в интерфейсе отключено.
В `.env` пользователя автоматических изменений не внесено.

Ключ необходимо резервировать отдельно от БД, с ограниченным доступом. При
утере ключа отзывы восстановить нельзя. Утечка только БД не даёт открытый текст;
утечка БД вместе с ключом/захват приложения/сессии уполномоченного администратора
выходят за эту защиту. Fernet обнаруживает изменение ciphertext, но не защищает
от удаления всей строки владельцем БД или восстановления старого backup.

На локальной SQLite перед миграцией создан backup через SQLite backup API и
проверен `PRAGMA integrity_check`. Миграция добавляющая; количество новостей,
элементов галереи и пользователей после применения не изменилось. Для rollback
сначала сохранить новые отзывы, БД, media и ключ; не удалять таблицу отзывов ради
отката кода. Полное аварийное восстановление продакшена не проверено.

## Границы безопасности

- От перехвата в сети защищает HTTPS с действительным сертификатом. Существующие
  production-настройки требуют HTTPS и Secure cookies; сертификат, reverse proxy,
  HTTPS внешнего адреса и сетевое закрытие БД надо подтвердить на целевом сервере.
  При локальном HTTP транспортного шифрования нет. Это не end-to-end шифрование:
  сервер получает текст и шифрует его перед INSERT.
- Прокси должен заменять forwarded-заголовки; доверяется только явно заданный
  proxy через существующий запуск Waitress. Иначе все посетители за одним proxy
  могут делить IP-квоту. Не включать wildcard trusted proxy ради лимитов.
- Runtime DB-role должна быть без DDL/superuser; миграции выполняются отдельной
  ролью. Реальные grants PostgreSQL, firewall и конкуренция на PostgreSQL не
  проверены локальными SQLite-тестами.
- Нельзя перенести `/media/videos/` на прямую публичную выдачу nginx/IIS/CDN без
  повторения проверки публикации: иначе защита черновиков будет обойдена.
- Декодер видео не OS-sandbox. Протоколы/форматы ограничены, env без секретов,
  есть timeout и ограничения; на сервере дополнительно нужны минимальные права,
  запрет исходящей сети, CPU/RAM-квоты и обновления FFmpeg. pip-audit не аудирует
  содержимое нативного FFmpeg автоматически.
- IP-квоты ограничивают спам, но не гарантируют защиту от распределённого DDoS.
  Публичный сайт и открытый ящик требуют мониторинга и лимитов на reverse proxy.
- Источники правил: SECURITY.md, SECURITY_RESEARCH.md, SECURITY-BASELINE.md и
  применимые разделы переданного свода `Desktop/rules`. Денежные разделы не
  переносились в этот сайт. [Fernet](https://cryptography.io/en/latest/fernet/),
  [imageio-ffmpeg](https://pypi.org/project/imageio-ffmpeg/).

## Проверки

Команды: `manage.py test --noinput`, `manage.py makemigrations --check --dry-run`,
`scripts/security_smoke.py`, `python -m unittest scripts.test_deployment -v`,
`pip check`, `pip_audit -r requirements.txt --no-deps --disable-pip`,
production `check --deploy`/`migrate`/`collectstatic` в отдельной временной SQLite.

Детальные новые сценарии: `core/test_feedback_video.py`. Используются только
синтетические отзывы и видео. Обход прав, инъекции и HTTP-атаки запускаются
локально; атаки на работающий сайт учебного заведения не выполнялись.

Итог первого этапа (до дополнительного backend-аудита): **109 Django-тестов: 108 прошли, 1 пропущен**
(создание symlink в Windows требует дополнительных прав). Включены 23 новых
теста отзывов/видео, в том числе конкурентная отправка на SQLite и проверка
загрузки настоящего файла через форму admin. Дополнительно прошли **36 HTTP smoke
проверок** и **7 тестов развёртывания**. `pip check`, проверка отсутствия новых
миграций и `git diff --check` прошли. `pip-audit` не обнаружил известных
уязвимостей в 16 закреплённых Python-пакетах; нативный FFmpeg этим не сертифицирован.

Изолированные production check, чистые миграции и collectstatic прошли. Остались
два прежних предупреждения Django: HSTS include-subdomains и preload отключены
до подтверждения HTTPS всех поддоменов. Защитные тесты включают CSRF/Origin,
инъекции SQL/HTML, нарушение прав просмотра/редактирования, подмену шифротекста,
спам/гонки квот, поддельные файлы/playlist, timeout декодера и некорректный Range.
При review исправлена атомарность двух квот: отклонённая отправка больше не
расходует чужую общую квоту, а после достижения общей квоты новые IP не
создают неограниченно новые строки счётчика.

**NOT TESTED: визуальная проверка адаптива в браузере.** Повторная инвентаризация
Computer Use вернула `The browser access host is unavailable`, браузерных
подключений нет. Проверены шаблоны, HTTP-вывод и CSS-правила; снимки реальных
экранов 320/375/768/1024/1440 px и воспроизведение на настоящих мобильных
браузерах не получены. Производственный HTTPS, ACL, DB grants, PostgreSQL,
reverse proxy, OS-изоляция декодера и восстановление prod-backup также NOT TESTED.
Наличие отчёта не означает абсолютную безопасность или завершённый выпуск.
