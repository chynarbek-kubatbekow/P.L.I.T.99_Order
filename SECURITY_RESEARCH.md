# Анализ проекта по четырём подборкам безопасности

Дата: 28 октября 2026 года. Результат текущего этапа: **86 тестов, 85 прошли,
1 пропущен; 36 HTTP-проверок прошли**. Добавлен 31 тест и исправлены три причины
риска. Полная неуязвимость сайта этим не подтверждается.

дополнительным аудитом сайта и не активировались. Не утверждается, что прочитана

агенты, hooks, SQLmap и другие инструменты из подборок не устанавливались.

## Модель приложения и границы доверия

Проект — Django с серверными шаблонами, ORM, новостями, галереей, Django admin,
Pillow и Waitress. Публичные обработчики читают опубликованный контент. Изменения
выполняются через admin с серверными правами и CSRF. Отдельного REST/GraphQL API,
регистрации, OAuth/SAML/JWT-входа, платежей, XML-импорта и распаковки архивов в
текущем коде нет. `/healthz/` — публичный JSON liveness, а не API доступа к БД.

Проверялись анонимный посетитель, обычный пользователь, staff без прав,
staff только с просмотром и superuser на искусственных данных. Superuser по
назначению имеет доступ к административным данным. Для новостей нет модели
владельца/tenant: право `change_news` относится ко всем новостям. Многопользовательская
изоляция по владельцу не заявляется и не добавляется без изменения требований.

Параметры HTTP, cookie и заголовки считаются недоверенными. Содержимое БД также
проверяется при HTML-выводе, поскольку импорт или старые записи могут обойти
`Model.save()`. Системные файлы/env и права операторов — отдельная граница:
доступ владельца ОС или к SECRET_KEY нельзя исправить скрытием URL.

## Подтверждённые находки и исправления

### R1. Разные Unicode-имена обходили лимит аккаунта

Связанные материалы: [Account Takeover](https://github.com/swisskyrepo/PayloadsAllTheThings/blob/3ac27901c711bdf3f5b65a7b1d1820a1f65bd09a/Account%20Takeover/README.md),
[Encoding Transformations](https://github.com/swisskyrepo/PayloadsAllTheThings/blob/3ac27901c711bdf3f5b65a7b1d1820a1f65bd09a/Encoding%20Transformations/README.md),
[Brute Force Rate Limit](https://github.com/swisskyrepo/PayloadsAllTheThings/blob/3ac27901c711bdf3f5b65a7b1d1820a1f65bd09a/Brute%20Force%20Rate%20Limit/README.md).

Вход Django применяет NFKC, поэтому полноширинные буквы соответствуют обычному
имени. Счётчик раньше использовал только `strip().casefold()`. После исчерпания
лимита обычного имени вариант Unicode с другого IP получал 200 вместо 429.
Это обход ограничения перебора, **не вход без правильного пароля**; IP-лимит
оставался активным. Оценка: средняя серьёзность, воспроизведено тестом до исправления.

В `core/middleware.py` ключ аккаунта теперь строится через
`get_user_model().normalize_username(...)`, согласованно с Django. Вход ограничен
254 символами перед нормализацией, чтобы не создавать дорогую обработку длинной
строки. Добавлены проверки работоспособности Unicode-входа, общего бюджета
вариантов и дублирующихся параметров. В регрессии время фиксируется: запросы
должны находиться в одном пятиминутном окне, иначе переход окна легитимно
восстанавливает бюджет и делает тест нестабильным.

### R2. Настройки допускали размещение данных в static

Связанные материалы: [API Key Leaks](https://github.com/swisskyrepo/PayloadsAllTheThings/blob/3ac27901c711bdf3f5b65a7b1d1820a1f65bd09a/API%20Key%20Leaks/README.md),
[Directory Traversal](https://github.com/swisskyrepo/PayloadsAllTheThings/blob/3ac27901c711bdf3f5b65a7b1d1820a1f65bd09a/Directory%20Traversal/README.md)
и [Insecure Source Code Management](https://github.com/swisskyrepo/PayloadsAllTheThings/blob/3ac27901c711bdf3f5b65a7b1d1820a1f65bd09a/Insecure%20Source%20Code%20Management/README.md).

Старые настройки успешно загружались с `APP_DATA_DIR=static`/`staticfiles` и с
SQLite, указанной внутри этих каталогов. Эти каталоги предназначены для публичной
раздачи WhiteNoise; ошибочно помещённая туда БД/копия создаёт риск прямой утечки.
Текущая рабочая база расположена вне этих каталогов; **её утечка не обнаружена**.
Оценка: высокий потенциальный ущерб при неправильной конфигурации, не доказанная
эксплуатация текущей установки.

Добавлен запрет расположения data-dir и SQLite под public static, включая
разрешённые реальные пути. Для SQLite дополнительно запрещён каталог public media.
Проверка выполняется при загрузке настроек, до создания data-dir. Тесты показывали
успешную загрузку небезопасной конфигурации до изменения и отказ после него.
Обычная локальная конфигурация, production и допустимые приватные пути продолжают
загружаться.

### R3. Production мог понизить проверку TLS PostgreSQL

`sslmode=verify-full` раньше задавался через `setdefault`, поэтому `DATABASE_URL`
с `disable`, `prefer` или `require` мог переопределить безопасное значение.
Это риск конфигурации удалённого соединения, а не найденная SQL-инъекция. Текущая
локальная SQLite этим не затронута. Оценка: средняя серьёзность при использовании
удалённой БД и недоверенной сети.

Теперь production принимает для PostgreSQL только `verify-full`. Проверены
отклонение пяти более слабых вариантов и загрузка правильной конфигурации.
Соединение с реальным PostgreSQL в этих тестах не открывалось. Режим обеспечивает
проверку цепочки доверия и имени сервера; требование сверено с
[официальной документацией libpq](https://www.postgresql.org/docs/current/libpq-ssl.html).
При переходе на PostgreSQL нужны правильный hostname, сертификат и доверенный CA.

## Матрица применимых направлений

В таблице «пройдено» относится к перечисленному сценарию, а не ко всем вариантам
атак этого класса. Тесты в основном находятся в `core/test_documentation_security.py`;
предыдущие проверки сохраняются в `core/test_security.py` и `core/test_access_control.py`.

| Направление из источников | Что рассмотрено в проекте | Проверка / результат |
| --- | --- | --- |
| Account Takeover, сессии | Фиксация ID, logout, смена пароля, отзыв staff | Старый ID не даёт входа; logout/смена пароля/отзыв staff закрывают доступ. |
| Перебор, HPP, Encoding | Unicode-эквиваленты, разные IP, повтор username | R1 исправлен; лимит и форма используют одну идентичность. |
| Race Condition | Общий атомарный счётчик процессов | Прежний конкурентный тест проходит на SQLite; PostgreSQL под нагрузкой не проверен. |
| IDOR / broken access control | Чтение, изменение, удаление и bulk action с чужим ID без прав | Права проверяются сервером; закрытые данные не возвращаются, записи сохраняются. |
| Mass Assignment / hidden parameters | is_superuser, role, is_published и дополнительные query-параметры | Подмена роли не авторизует и не изменяет записи; прежние проверки сохранены. |
| ORM Leak | `password__startswith`, `__regex`, relational lookups, JSON-подобные имена параметров | Публичные handlers не распаковывают клиентский словарь в `.filter(**...)`; черновики не выдаются. |
| SQLi / SQLite / PostgreSQL | Boolean/stacked-подобные строки в фильтрах и входе | ORM использует фиксированные имена полей и параметры; прежние SQLi-тесты проходят. Системные команды БД не запускались. |
| SSTI / Python / Django | Арифметика, debug, include и доступ к signer через текст новости | Текст остаётся данными; выражение не вычисляется, SECRET_KEY не появляется в ответе. |
| Stored/reflected XSS | Старые строки БД, заголовки/выдержки, HTML и entity encoding | Санитизация при выводе сохранена; недоверенные заголовки экранируются. |
| mXSS / DOM Clobbering | SVG/MathML, повреждённая вложенность, id/name, опасные схемы | После очистки не остаются запрещённые элементы/атрибуты. Реальная браузерная мутация отдельно не подтверждалась. |
| CSS Injection | style, import, URL и attr()-подобные значения | Стили пользователя удаляются, градиенты ограничены; произвольный CSS не выводится. |
| CSP / Clickjacking | script-src, object-src, frame-ancestors, X-Frame-Options | Заголовки проверены; CSP — дополнительный уровень. Google script-host и inline styles остаются для текущих интеграций/вёрстки. |
| CORS | Отражение Origin, `null`, похожий домен | Нет ACAO/credentials для атакующих origins, в том числе на авторизованной admin-странице. CORS не считается авторизацией. |
| CSRF | text/plain/JSON/form, поддельный token, Origin, Referer по HTTPS | Изменяющие запросы отклоняются, записи не создаются. |
| Open Redirect / CRLF | //, обратные слеши, userinfo, javascript, переносы | `next` не отправляет пользователя на чужой сайт и не добавляет заголовки. Штатное добавление slash может дать безопасный 301. |
| Reverse Proxy / Virtual Hosts / DNS Rebinding | Host, forwarded-host, original-url и rewrite-url | Чужой Host отклоняется; заголовки не превращают healthz в административный handler. Реальный DNS-rebinding не проводился. |
| Request Smuggling | Конфликт длины, отрицательная длина, gzip TE, повреждённые chunk sizes | Direct Waitress вернул 400/501. Это не проверка смuggling через IIS/CDN и HTTP/2 downgrade. |
| Web Cache Deception / XS-Leak | CSS/JS-суффиксы у admin и private/no-store | Поддельный static-путь не отдаёт административную страницу; прежняя проверка cache headers проходит. Браузерные timing-оракулы не тестировались. |
| Upload Insecure Files | Двойные расширения, config/py/ADS-подобные имена, GIF/SVG/ZIP | Валидные изображения получают случайное имя JPEG; неподдерживаемые данные отклоняются. |
| Metadata / image polyglot | EXIF и данные после конца изображения | EXIF и тестовый appended marker отсутствуют в перекодированном результате. Это не доказательство удаления любых steganographic payload из пикселей. |
| Ошибка декодирования | Искусственный OSError при обработке валидной загрузки | Исходник не сохраняется, записи нет; fail-open fallback отсутствует. |
| Directory Traversal / LFI / SCM | .., slash/backslash, двойное кодирование, `.git/index`, SVN/HG, backup/env/SQLite | В HTTP-проверках файлы не выдаются. Реальный symlink-тест пропущен из-за Windows; это остаётся ограничением. |
| SSRF | Необычные IPv4/IPv6, metadata, gopher/file, deceptive hosts | Видеопарсер отклоняет такие URL. У приложения нет backend-функции скачивания произвольного URL; реальные metadata-сервисы не опрашивались. |
| Zip Slip | ZIP с `../` в имени записи, загруженный как JPEG | Архив отклонён; серверной распаковки в приложении нет. |
| DoS / ReDoS | Лимиты тела/полей/пикселей/файла, ошибки декодирования, регулярные выражения | Небольшие отрицательные сценарии проходят; нет вложенного пользовательского regex. Массовое истощение памяти, диска и процессов не запускалось. |
| Insecure Randomness | SECRET_KEY, sessions, upload UUID, публичный slug | Для ключа применяется secrets, sessions — штатный Django. Slug/имя файла не являются правом административного доступа. |
| Dependency Confusion / CVE | Закреплённые версии, wheel, сканирование зависимостей | 12 runtime-пакетов, pip-audit известных уязвимостей не нашёл. Полный аудит цепочки поставки и всех Git-коммитов не заявляется. |

## Матрица неприменимых и инфраструктурных техник

Эти главы тоже рассмотрены по пояснениям/методикам. Отсутствие компонента означает
неприменимость к текущему коду, а не успешный эксплуатационный тест этой технологии.

| Группа глав PayloadsAllTheThings | Причина / граница |
| --- | --- |
| IIS Machine Keys, ViewState, .NET gadgets | IIS может быть reverse proxy, но Django-приложение не реализует ASP.NET Forms Authentication/ViewState. Сам IIS в этом этапе не аудировался. |
| Java RMI/JMX, GWT, Struts, Log4Shell, Java deserialization | В Python runtime/зависимостях нет JVM/RMI/GWT/Log4j. Связанные системные службы вне проекта не атаковались. |
| PHP wrappers, PHAR, .htaccess, PHP deserialize, type juggling | Нет PHP-интерпретатора или `include/unserialize` в приложении. Пути/загрузки всё равно проверены общими сценариями. |
| Ruby Marshal/YAML, ERB/Slim/Liquid | Эти runtime и шаблонизаторы не используются. |
| SSTI Java/JS/PHP/Elixir и Jinja/Mako/Tornado | В Django настроен DjangoTemplates; динамической компиляции пользовательского шаблона не обнаружено. Django-выражения проверены отдельно. |
| Node deserialize, server-side prototype pollution | Сервер Python. В имеющемся frontend не обнаружено чтение JSON/query в deep merge; `innerHTML` теста профессий строится из локальных констант/результатов. Это анализ источника, не динамический browser pentest. |
| Angular/CSTI | Angular отсутствует; ng-app или клиентский шаблонизатор не используются. |
| JWT, OAuth, SAML и MFA bypass | Таких способов входа и MFA в проекте нет. Используются Django sessions. Отсутствие MFA — остающийся уровень риска кражи пароля; «MFA защищена» не заявляется. |
| GraphQL, WebSocket, Socket.IO | Соответствующих серверов/маршрутизации нет. Предполагаемые API-пути ранее проверены на отсутствие доступа; строгой инвентаризации всех настроек внешнего proxy нет. |
| NoSQL, MongoDB operators, Cassandra | Бэкенды БД ограничены SQLite/PostgreSQL, Mongo/Redis query endpoints нет. |
| MySQL/MSSQL/DB2/Oracle/BigQuery SQLi | Эти движки не используются и не допускаются настройками проекта. Общие SQLi-принципы применены; их специфические функции не запускались. |
| XXE, XPath, XSLT, SVG XML, SOAP | Нет XML endpoint/импорта/трансформации. SVG не принимается как изображение. Реальный XML-parser exploit не заявляется. |
| LaTeX, PDF/headless rendering, ImageMagick, FFmpeg | Нет серверного конвертера документов/видео или браузера, обрабатывающего URL посетителя. Изображения обрабатывает Pillow. |
| CSV/Excel formula injection | CSV-export отсутствует. При добавлении экспорта потребуются отдельные защиты формул, HTML-санитизация их не заменяет. |
| Финансовая логика, купоны, refund, rounding | Платежей, корзины и финансовых операций нет. Публикация и права контента проверены; истинность фактов новости определяется редакцией. |
| Cloud metadata, FastCGI/Redis/Memcached/Zabbix SSRF chains | Нет backend URL-fetch и этих интеграций. Наличие внешней облачной инфраструктуры требует отдельного аудита. |
| Active Directory, persistence, escalation, shells, AMSI и internal pivoting | В данном репозитории страницы являются указателями на другой проект. ОС, домен и защитные настройки не изменялись, payload не исполнялся. |
| Browser exploitation, sandbox escapes, XS timing attacks | Нужны реальные браузеры/версии и отдельная лаборатория. Исправления сайта не являются патчем V8/WebKit/ОС. |
| WAF bypass и TLS | WAF не установлен этим изменением. TLS, IIS/CDN и внешняя сетевая доступность требуют проверки именно развернутой цепочки. |

## Проверка результатов и повторение

```powershell
.\.venv\Scripts\python.exe manage.py test --noinput
.\.venv\Scripts\python.exe scripts/security_smoke.py
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
.\.venv\Scripts\python.exe -m pip check
.\.security-venv\Scripts\python.exe -m pip_audit -r requirements.txt --no-deps --disable-pip
```

Выполнено на Python 3.14.4 в проектном `.venv`. Команда аудита зависимостей
использует отдельное окружение инструментов; она отправляет названия/версии
публичных пакетов, а не исходники сайта или секреты. Первые 55 тестов существовали
до этого этапа, 31 добавлен по документам. Всего **86, успешно 85, пропущен 1**.
HTTP-smoke использует свою временную БД и loopback-порт; **36 проверок прошли**.

## Остаточные риски

Нет проверки с внешней машины и полноценного браузерного pentest: браузерная
автоматизация в предыдущем этапе была недоступна. CSP с разрешённым сторонним
script-host и inline styles нельзя представлять как универсальную защиту от XSS;
основная защита rich text — allowlist-санитизация. Для более строгой CSP нужны
nonce/hash и проверка работы аналитики в браузере.

Временная блокировка по имени может использоваться для отказа во входе этому
пользователю; фиксированные окна допускают всплеск на границе. Нужны доступ к
админке через VPN/IP/MFA и rate limit на proxy для публичной эксплуатации.
Нагрузочное DDoS-тестирование и конкурентный PostgreSQL-тест не выполнялись.

Сетевые и NTFS-наблюдения прошлого этапа находятся в [ACCESS_RECHECK.md](ACCESS_RECHECK.md):
PostgreSQL слушал все интерфейсы, хотя сайт использует SQLite, а его HBA требовал
локальный SCRAM-вход. Эти наблюдения не заменяют свежую внешнюю проверку firewall.
Эксплуатационные шаги и восстановление описаны в [SECURITY.md](SECURITY.md).
